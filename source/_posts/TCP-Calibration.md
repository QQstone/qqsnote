TCP 标定需要区分两个目标：确定工具工作点的位置，以及确定工具坐标系的方向。伸缩针可以通过两个长度状态测出针尖位置和伸缩轴方向，但不能仅凭轴线上两个点确定绕轴旋转。

## 两种“六点法”不是同一件事

| 方法 | 采样组成 | 位置结果 | 方向结果 |
| --- | --- | --- | --- |
| 本文讨论的传统六点法 | 3 个定点接触姿态 + 3 个方向示教点 | TCP 的 XYZ | 两个不平行方向可建立完整工具坐标系 |
| 伸缩针两状态法的最少采样方案 | 短针 3 个接触姿态 + 长针 3 个接触姿态 | 两个长度状态下的针尖 XYZ | 两点连线确定工具轴，绕轴角未知 |
| 项目 Web UI 的采样配置 | 短针 6 个姿态 + 长针 8～12 个姿态 | 同上，增加冗余约束 | 同上，增加样本不会使绕轴角可观测 |

这里的“接触姿态”是机器人位姿记录，不是互不相同的空间接触点。每轮采集都让针尖反复触碰同一个固定点，同时改变机器人末端姿态。

不同控制器对“六点法”的点序、轴向和正负号可能有不同约定，实际示教以对应设备手册为准。下文的传统方法特指“前三点求位置，后三点定义 X/Z 方向”的流程。

## 定点变姿态为什么能求 TCP 位置

约定所有样本使用同一个机器人基坐标系，待求 TCP 偏移表达在法兰坐标系中。第 i 次接触时：

- R_i：法兰到基坐标系的旋转矩阵。
- p_i：法兰原点在基坐标系中的位置。
- t：针尖在法兰坐标系中的位置，采集期间保持不变。
- c：固定接触点在基坐标系中的位置。

每次接触都满足：

```text
R_i · t + p_i = c
```

与第一条样本相减，消去未知固定点 c：

```text
(R_i - R_1) · t = p_1 - p_i
```

堆叠所有样本后得到 A·t=b，用最小二乘求解 t。也可以同时拟合 t 和 c；在存在测量噪声时，不同拟合形式的统计性质可能不同。

固定点不必事先精密测量坐标，但在同一轮内必须保持不动。参考点记录可以用于接近位置规划，不应把粗参考点当作精密已知坐标强加给求解器。

如果数据源提供的是已经叠加旧工具偏移的 TCP 位姿，应先还原法兰位姿，或明确改用另一统一的安装参考系。不能把旧 TCP 位姿直接当作法兰位姿。`rx/ry/rz` 还必须明确对应的旋转顺序、内外禀约定和角度单位。

## 传统六点法：位置标定加方向示教

本文讨论的流程为：

1. 前三个姿态：工具尖端从不同姿态触碰同一固定点，求 TCP 位置。
2. 第四点：按设备规定摆好工具参考姿态，例如使工具轴垂直于参考面，记录参考位置 P4。
3. 第五点：按规定沿期望的工具 +X 方向平移，记录 P5。
4. 第六点：相对参考位置按规定沿期望的工具 +Z 方向平移，记录 P6。

“垂直于固定点”不是严格的几何定义：一个点本身没有法向。现场所谓垂直，实际应指垂直于某个参考面，或平行于明确的参考轴。

后三点按控制器要求保持规定的末端姿态，提供两个方向向量：

```text
v_x = P5 - P4
v_z = P6 - P4
```

例如，以 Z 方向为优先轴，可构造右手坐标系：

```text
z = normalize(v_z)
x = normalize(v_x - (v_x · z) z)
y = z × x
R = [x y z]
```

两个向量不能平行。若控制器优先固定 X 轴，正交化顺序会不同。

该方法的关键在于方向基准：操作者如何准确知道真正的 X、Z 方向？精密直角检具、导轨或其他外部方向基准可以提供约束；目测摆正和手动定向则会引入方向误差。

还应区分“定义期望坐标系”和“测量真实机械轴线”。如果只是用旧工具帧的 Z 方向 JOG，再把这段轨迹作为真实工具 Z，就不能独立识别旧工具帧相对真实轴线的倾斜。

## 伸缩针两轮标定

### 准备条件

- 两轮之间安装座不动，针尖与安装坐标系的关系只因伸缩而改变。
- 伸缩运动具有稳定的直线方向，两种长度状态均可重复定位并固定。
- 每轮采集期间长度不变，接触不能使针明显回缩、侧移或弯曲。
- 固定接触点稳定，机器人位姿记录与实际接触状态一致。
- 标称行程指长、短状态的长度差，不是长针总长度。

伸缩机构的轴线必须与目标工具轴具有明确的机械关系。如果标定针导向机构本身装偏，测到的就是装偏后的导向轴。

### A 段：短针位置

将针固定在缩回状态，让针尖从不同姿态触碰同一固定点，分别记录位姿。独立求解得到短针尖位置 t_A。

项目 Web UI 要求 A 段恰好采集 6 个姿态，通过质量检查后进入 B 段。

### B 段：长针位置

将针伸出到稳定状态，重新执行定点变姿态采集，独立求解得到长针尖位置 t_B。项目 Web UI 要求 8～12 个姿态。

两轮姿态不需要一一对应。两轮也可以使用不同的固定点：只要各轮内部固定点不动，且 t_A、t_B 表达在同一个安装坐标系下即可。现场沿用同一个固定点通常更容易操作。

### 由两点连线求轴向

```text
d = t_B - t_A
L = ||d||
u = d / L
行程偏差 = L - 标称行程
```

若约定伸出方向为工具 +Z，则工具 Z 轴为 u。若实际工具采用相反约定，应明确处理符号。

方向来自实测差向量归一化，标称行程用于偏差对照，不替代方向测量。也不能把两轮机器人在基坐标系中的位置直接相减：机器人已经变换过姿态，必须先各自求出安装坐标系内的针尖位置。

短针尖可以作为 TCP 原点，但要区分“针尖”和“实际工作点”。只有短针尖准确代表打磨工作面中心，或两者之间的偏移已知时，才能将标定结果转换为打磨 TCP。

## 最少需要几个姿态，如何摆放

### 独立求解两段时，最少是 3+3

在不额外引入已知长度或机构约束、分别独立求解两个针尖位置的方案中，每段至少需要 3 个满足非退化条件的姿态，共 6 次接触记录。

原因是：两个姿态只有一个相对旋转，其旋转轴方向不受差分方程充分约束；加入第三个姿态，并使相对于基准的两次旋转轴不平行，堆叠矩阵才可能达到求位置所需的秩 3。

这个“3+3”是当前独立求解方案的下限，不是所有带额外约束的联合标定算法的全局最小采样结论，也不是完整六自由度标定的保证。

### 一个最少采样摆法

以第一姿态为基准，并用该基准下两个不同的横向轴定义倾斜方向：

| 姿态 | 摆放示例 |
| --- | --- |
| 1 | 选取便于接触、关节远离限位的基准姿态 |
| 2 | 相对基准绕 X 方向倾斜约 +15°～25° |
| 3 | 相对基准绕 Y 方向倾斜约 +15°～25° |

每次倾斜后都需要调整位置，让针尖重新回到同一个固定点。角度只是现场起点建议，应结合可达性、碰撞空间和接触条件调整。

### 更稳妥的 6+8 摆法

A 段可采集：基准、X 正倾、X 负倾、Y 正倾、Y 负倾、一个 X/Y 组合倾斜。B 段在此基础上增加其他象限的组合倾斜，有需要时继续补到 12 个。

优先增加不同方向、足够角度的倾斜，不要只重复近似姿态，也不要只绕针轴自转。长针更容易受接触挠曲影响，增加样本有助于检查一致性，但不能消除系统性的弯曲偏差。

严格的退化判断依据是方程组的秩和条件数，不能简单用“针轴方向是否共面”作为唯一判据。姿态数量足够也不代表几何约束良好。

### 每次接触的操作顺序

1. 在离开固定点后调整姿态，先到保留间距的接近位置 standoff。
2. 低速 JOG 微调，让针尖轻触固定点。
3. 确认没有压弯、滑动或回缩，机器人稳定后记录实际位姿。
4. 退离接触点，再切换下一个姿态。

项目已有 Qt 流程采用 10 mm 接近间距；这属于具体实现参数，不是适用于所有工具和误差范围的通用安全距离。

## 伸缩针解决了传统六点法的什么问题

核心变化是：将“人工准确摆正和沿轴示教”转化为“测量机械伸缩机构两个状态下的针尖位置”。

| 对比项 | 传统方向示教 | 伸缩针两状态测量 |
| --- | --- | --- |
| 轴向基准 | 摆正动作、平移方向或外部检具 | 伸缩机构的实际运动方向 |
| 是否要先准确摆出垂直姿态 | 按本文所述流程需要 | 不需要预先精确摆正 |
| 是否要专门沿真实工具轴示教直线 | 需要形成准确的方向线 | 不需要这条方向示教直线 |
| 工具轴与名义模型存在倾斜 | 取决于外部方向基准能否反映真实轴线 | 可测伸缩轴相对安装坐标系的实际倾斜 |
| 圆柱工具的方向确定 | 目测轴线困难，横向缺少特征 | 伸缩运动提供轴线，但仍不提供绕轴角 |
| 主要误差来源 | 接触、人工定向、外部检具和机器人位姿误差 | 接触、伸缩直线度、间隙、挠曲和机器人位姿误差 |

例如真实主轴相对名义 Z 倾斜 2°，沿旧工具 Z 进行 JOG 只会重现旧方向。若伸缩针与真实主轴同轴，测得两针尖连线就能体现这个倾斜。

传统方法若使用准确外部检具，同样可以测得真实轴向。伸缩针的优势在于减少对人工方向示教和外部方向基准的依赖，并不意味着天然比传统六点法精度更高。

## 不能测出的绕轴旋转

沿同一轴线的两个点只能确定一条有向直线。将工具绕这条轴旋转，两个点的位置不变，因此无法从测量中恢复该旋转。

伸缩针提供的是 3 个位置自由度和轴线的 2 个方向自由度。绕轴旋转必须通过以下方式之一补齐：

- 对绕轴对称工具，按约定沿用参考工具帧方向。
- 增加不在轴线上的已知特征或第三个检具点。
- 使用外部方向检具、视觉特征或额外方向示教。

若沿用参考帧，可以构造最小旋转，将参考 Z 对齐到实测 u，再作用到整个参考旋转矩阵。这样得到的是参考约定下的完整工具帧，并非测出了缺失的自由度。

“保留绕轴参考方向”不等价于简单保留某一个欧拉角。欧拉角之间存在耦合，应先在旋转矩阵或四元数层面处理，再按控制器约定转换。

## 误差、验收与独立验证

### 单段质量

求得 t 后，各次预测针尖位置为 c_i=R_i·t+p_i。以其平均位置为中心计算空间距离 RMS，衡量定点接触的一致性。

- RMS 大：检查接触重复性、针变形、固定点移动、反馈同步和坐标约定。
- 条件数大：说明姿态分布导致求解对噪声敏感，应增加或更换倾斜方向。

RMS 衡量样本内部一致性，不能直接当作最终绝对定位精度。重复性很好的系统误差仍可能存在。

### 方向误差与伸缩行程

小误差下：

```text
方向误差（弧度）≈ 两端位置差的横向误差 / 伸缩行程
```

若两段位置误差独立，横向标准差分别为 σ_A、σ_B，则对应差值误差可近似按 sqrt(σ_A²+σ_B²) 估计。实际位置不确定度不能直接用接触 RMS 替代。

相同位置误差下，增加行程有利于方向分辨，但长针可能更容易弯曲，应结合刚度和重复定位能力选择行程。

### 项目门槛与独立验证

当前 React Web UI 的门槛为：

| 检查项 | 通过条件 |
| --- | --- |
| A 段样本数 | 恰好 6 个 |
| B 段样本数 | 8～12 个 |
| 两段各自 RMS | 小于 1 mm |
| 两段各自条件数 | 小于 50 |
| 实测行程 | 不小于 10 mm |

这些是项目配置，不是通用行业验收标准。标称行程偏差仅展示，尚未设为独立阻断阈值。

应用前应使用未参与求解的姿态重新触点，检查工作点位置；再用独立方向基准检查轴向。若用于打磨，还应验证检具针尖到实际工作面中心的转换关系。

## 项目 Web UI 的实现边界

核对日期：2026-09-21。

PolishStation 的 React Web UI 引导顺序为：准备 → 短针 A → 长针 B → XY/方向计算 → 验收应用。当前仍是 Mock 流程：

- 采样使用预设位姿，真实机器人采样和运动尚未接入。
- 单段 XYZ 使用预设结果，RMS 和条件数没有通过真实矩阵求解获得。
- “记录参考点”仅保存已记录标志。
- 应用修改前端专用标定针工具状态，尚未下发真实控制器或接入结果归档服务。
- Mock 姿态应用保留旧 RPY 第一项并写入演示方向角，不能视为通用的参考帧最小旋转实现。

仓库已有 Python 定点最小二乘与两状态方向算法，但不能据此认定 React 页面已经接通真实求解链路。
